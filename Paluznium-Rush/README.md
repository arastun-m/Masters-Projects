# Paluznium Rush: Genetic Algorithms for Optimised Separation Circuits

This project is a C++ application designing an optimised separation circuit for Gormanium/Palusznium using a Genetic Algorithm, which can also handle both discrete & continuous circuit configurations, balance economic value and waste penalties, ensure robustness, flexibility, and tunability via configuration.

---

## Features

1. **Simulator**: Model a circuit and calculate its performance.

2. **Genetic Algorithm**: Algorithm implemented to find the optimal separation circuit.

This library implements three flavours of genetic algorithms:

- **Discrete GA**: evolves circuit topologies encoded as integer vectors.  
- **Beta-Only GA**: evolves continuous β-parameters for a _fixed_ circuit topology using SBX crossover and Gaussian mutation.  
- **Hybrid GA**: co-evolves both discrete topology **and** continuous β in one run.

Each GA shares the same core loop (selection, crossover, mutation, elitism, stall criterion), but overrides population initialisation and genetic operators to suit discrete, continuous, or mixed representations.

## Project structure

### Simulator

Our simulator is composed of three core components designed to evaluate processing circuits:

1.  **Unit Recovery Calculator**:
    - Residence Time Calculation: 
    $$ \tau = \frac{\phi \cdot V}{\sum_{i} \frac{F_i}{\rho_i}} $$

    - Recovery Calculation: 
    $$ R_i^C = \frac{k_i \cdot \tau}{1 + k_i \cdot \tau} $$

    - Stream Routing & Product Accumulation: 
    $$ C_i = F_i \cdot R_i^C $$
    $$ T_i = F_i - C_i $$


2.  **Flow Simulation**: 

This component models the overall circuit flow using a Successive Substitution Algorithm. The brief steps are as follows:

* **1. Initialisation**
    - Zero out the feed, concentrate, and tail streams for every unit in the circuit.
    - Inject the overall circuit's fresh feed at the designated feed_index unit(s).

* **2. Compute Unit Outputs**
    - Calculate the concentrate and tailings streams for each unit in the circuit, by invoking its Unit Recovery Calculator and use its current feed stream as input. 
    - This is represented by a call like `CUnit::calculateOutputs()`.

* **3. Stream Routing**
    * 3.1 Route each unit's calculated concentrate and tail streams to the appropriate downstream units or global product/waste bins.
    * 3.2 Add the materials from streams exiting the circuit to their corresponding global product arrays (e.g., final concentrate, final tailings).

* **4. Convergence Check**
    * 4.1 The feed to recycle streams (and thus to units receiving these streams) is updated based on the outputs from the previous iteration.
    * 4.2 Convergence is checked by comparing the maximum difference in stream compositions or flow rates between the current and previous iteration against a predefined tolerance (`tol`).
    * The simulation continues iteratively (repeating steps 2-4) until the `max_d` (maximum difference) is less than `tol`, or a maximum number of iterations (`max_iters`) is reached to prevent infinite loops. If `max_iters` is reached without convergence, a warning is typically issued.

    The simulation includes a maximum iteration limit to prevent infinite loops and ensure computational efficiency.

3.  **Profit Calculator**: 

This module assesses the economic viability of a given circuit configuration. The calculated total profit serves as the fitness score, guiding the genetic algorithm's optimization process.

* **1. Economic Value of Product Streams**
    The value is determined from the product streams, considering income from valuable materials and costs for impurities or waste:
    
    - **Palusznium Stream**: Income of +120 per unit of Palusznium (pal), cost of -20 per unit of Gormanium (gor) impurity, cost of -300 per unit of waste.
    
    - **Gormanium Stream**: Income of +80 per unit of Gormanium (gor), cost of -25 per unit of waste.

* **2. Operating Cost**
    Operating costs are primarily based on the volume of the units:
    - **Base Cost**: $5 \times (\text{volume})^{2/3}$
    - **Penalty Cost**: An additional $1000 \times (\text{volume} - 150)^2$ if total volume exceeds 150.

* **3. Total Profit Accumulation**
    The total profit is the sum of the economic values from all product streams minus the total operating costs:
    $$ \text{Total Profit} = (\text{value}_1 + \text{value}_2 + \dots) - \text{Total Operating Cost} $$

* **4. Fitness Function (`circuit_performance()`)**
    This function encapsulates the entire simulation (Unit Recovery, Flow Simulation, and Profit Calculation) for a given circuit configuration (genome).
    - Return a profit score directly used by the genetic algorithm.

4.  **Extension**: for volume parameterization allows for handling units of variable sizes.

## Genetic Algorithm

This library implements three flavours of genetic algorithms.

The discrete GA follows the standard flow:

1.	init_population: randomly generate valid circuits.

2.	select_parents / select_tournament: pick two parents via tournament selection.

3.	crossover: single-point swap of integer genes with probability cross_prob.

4.	mutate: each gene may be re-sampled with probability mutate_prob, enforcing validity rules.

5.	optimize: repeat for max_iterations or until stall_iterations without improvement.



### Beta-Only GA

init_population_beta(...)

•  Purpose: seed a population of size pop_size—each Individual carries the same fixed discrete topology and a random β vector.

•  Mechanics:

  1.  Copy the provided fixed_topology into each Individual.

  2.  Repeatedly sample each beta[i] ∼ Uniform(0,1) until the val(...) function accepts it.

  3.  Evaluate fitness = fit(..., beta.data()).


crossover_beta(...)

•  Purpose: recombine two parents’ β vectors via Simulated Binary Crossover (SBX).

•  Key steps:

  1.  With probability cross_prob, for each gene i draw u ∈ [0,1).

  2.  Compute SBX factor η-dependent:


if(u≤0.5) β = (2u)^(1/(η+1));

else      β = [2(1–u)]^(1/(η+1));

where η = 2.0 by default.

  3.  Offspring genes:

c1[i] = 0.5*((1+β)*x1 + (1–β)*x2)

c2[i] = 0.5*((1–β)*x1 + (1+β)*x2)


  4.  Clamp into [0,1] to avoid numerical drift.

•  Result: two new Individuals with mixed β, unchanged vector.



mutate_beta(...)

  •  Purpose: add Gaussian perturbations to each β with probability mutate_prob_real.

  •  Mechanics:

for (b in beta)
  if (Uniform(0,1) < mutate_prob_real)
      b ← clamp(b + Normal(0, real_sigma), 0, 1);


•  Result: spreads around parents in continuous space for local exploration.



optimize_beta(...)

•Flow:
  1.	Store GA hyperparameters.

  2.	Call init_population_beta.

  3.	Identify initial elite.

  4.	Loop: elitism → tournament selection → crossover_beta → mutate_beta → validity check → fitness eval → population replacement.

  5.	Stop on max_iterations or stall_iterations without improvement.

  6.	Write final best.beta and best.fitness back to caller.



### Hybrid GA (Topology + β)

init_population_hybrid(...)

•	Purpose: seed mixed individuals with both a random valid topology and random β.

•	Mechanics:

  1.	Randomly generate each vector using the same rules as discrete GA.

  2.	Randomly sample each beta ∼ Uniform(0,1).

  3.	Reject and retry if val(vector, beta) fails.

  4.	Evaluate fitness with the combined fit(vector, beta) callback.



crossover_hybrid(...)

•	Purpose: perform discrete single-point crossover on vector, and SBX crossover on beta.

•	Mechanics:

  1.	auto [c1, c2] = crossover(p1, p2)

  2.	auto [b1, b2] = crossover_beta(p1, p2)

  3.	c1.beta = b1.beta; c2.beta = b2.beta;



mutate_hybrid(...)

•	Purpose: apply both discrete mutation on vector and Gaussian mutation on beta.

•	Mechanics:

Individual tmp = mutate(in);         // discrete mutate

return mutate_beta(tmp);             // then real mutate





optimize_hybrid(...)

•	Combined flow:

1.	Sanity check topo_len == 2*n+1.

2.	Call init_population_hybrid.

3.	Elite initialization.

4.	Loop for each generation:

  •	Elitism

  •	Tournament selection (discrete‐only)

  •	crossover_hybrid → mutate_hybrid

  •	Validity & fitness check with combined callback

  •	Fill new population

5.	Replace old population, update best, track stall.

6.	Return final topology+β in best.


### Validity Check

Validity check is implemented using the following rules:

1. **Vector length and format**:
- Check: Verifies that the input vector has at least three elements, that (vec_size – 1) is even, and that vec_size == 1 + 2·n_units.
- How: In check_validity(), the first two if-statements return false unless these size conditions hold.

2. **Index bounds**:
- Check: Ensures the feed unit index vec[0] lies in the range [0, n_units).
- How: After computing n_units = (vec_size–1)/2, the code if (feed < 0 || feed >= n_units) return false; enforces this.

3. **Destination indices range**:
- Check: Confirms every concentrate/tails destination vec[1]…vec[vec_size–1] is between 0 and n_units+2 (inclusive).
- How: A loop over i=1…vec_size–1 does if (vec[i] < 0 || vec[i] > n_units+2) return false;

4. **No self-circulation and identical outputs**:
- Check: Forbids a unit’s concentrate and tailings both targeting the same next unit.
- How: In the per-unit loop, catches self-loops and enforces distinct targets.

5. **Reachability from feed to at least one exit**:
- Check: Verifies that starting at the feed, some path leads to a terminal (Palu, Gorm or Waste).
- How: The recursive mark_units(feed) sets exit_reached = true whenever a non-unit index is encountered.

6. **At least two distinct exits per unit**:
- Check: Confirms each unit can ultimately send material to at least two different terminal types.
- How: Builds a bitset<3> reachability map for each unit and iteratively propagates downstream exits until every unit’s bitset has at least two bits set.

7. **Parameter vector size and bounds (overload)**:
- Check: When parameters are provided, verifies that param_size == n_units and each parameters[i] lies in [0.0,1.0].
- How: In check_validity(vec_size, vec, param_size, parameters), it first calls the basic check and then loops to enforce these numeric bounds.
